# Boss Scaling System 1.20.1 — 2.0.2

Кандидат публикации 1.20.1-2.0.3 называется **DepthWard Boss Scaling**: Ниже — документация реализации 2.0.2.

Восстановление и исправление предоставленного `bossscalingsystem-1.20.1-2.0.1 (6).jar`.
Minecraft **1.20.1**, Forge **47.4.4+**, Java **17**, KubeJS **2001.6.5+** с Rhino/Architectury.

## Настройка

Положить новый JAR в `mods`, убрав старую версию мода. Скрипт — в `kubejs/server_scripts/boss_scaling.js`:

```js
BossScalingSystem.addEntityConfig('minecraft:zombie', [], 1.0)
```

Замените ID на своего босса. API сохранён: `addEntityConfig(entityId, sharedItems, scalePerPlayer)`.
Второй аргумент — **исключения**, которые остаются общими и не копируются. `[]` делает весь обычный дроп персональным. Пример исключения: `[Item.of('minecraft:rotten_flesh')]`.

При первом добавлении нового настроенного моба на сервер:

1. Берутся живые игроки (включая creative), кроме spectator, в том же измерении, на расстоянии **не более 40 блоков** от точной позиции моба. Это сфера, включая высоту.
2. UUID игроков сохраняются в данных моба. Пересчёта во время боя нет.
3. `HP = базовое максимальное HP × (1 + scalePerPlayer × max(0, N − 1))`.

При коэффициенте `1.0`: 1 игрок — 100% HP, 2 — 200%, 3 — 300%. При `0.5` каждый дополнительный игрок добавляет 50%. Прежнее значение по умолчанию Java-конфига `2.0` сохранено, но через KubeJS коэффициент задаётся явно. Итог ограничивается допустимым диапазоном атрибута Minecraft/сборки.

При смерти исходный набор выпавших предметов копируется **по одному полному набору каждому игроку, записанному при спавне**. Это одинаковый лут, а не независимый бросок таблицы на каждого игрока. Учитываются предметы из Forge `LivingDropsEvent`, включая стандартную экипировку. Предметы из списка исключений остаются в одном общем экземпляре. Отдельный игрок-убийца не требуется.

Каждая персональная копия — обычная зарегистрированная `minecraft:item` со своим UUID владельца в Forge persistent NBT. Только владелец получает её на клиент и может подобрать. Слияние с другими предметами заблокировано; стандартные воронки и вагонетки с воронкой не забирают личный лут. NBT предмета (имя, зачарования, дополнительные данные) сохраняется без добавления служебных меток в ItemStack.

Владельцы и масштабирование переживают сохранение/загрузку. Уход игрока, смерть игрока и новые участники не меняют список получателей. Если при спавне не было игроков, здоровье и дроп остаются обычными. `/reload` очищает реестр и заново выполняет server scripts; уже появившиеся мобы используют сохранённые настройки исключений и список игроков. Уже существующие мобы из старой версии не масштабируются повторно — для нового поведения нужен новый спавн.

Лут выпадает в мир; это не почта и не автоматическая выдача офлайн-игроку. Действуют обычные время исчезновения и физика предметов. Опыт не дублируется. Предметы, которые другой мод создаёт напрямую в обход `LivingDropsEvent`, не перехватываются. Сторонние системы автоматического сбора, обходящие стандартный подбор/воронки, требуют отдельной проверки. Не включайте второе персональное дублирование у того же босса в другом моде.

## Сборка и проверки

```bash
./gradlew build
./gradlew runGameTestServer -x downloadAssets
```

Нужна Java 17. На Windows: `gradlew.bat build` и `gradlew.bat runGameTestServer -x downloadAssets`.
Если зависимости уже есть в папке модов:

```bash
./gradlew -PlocalMods=/absolute/path/to/mods build
./gradlew -PlocalMods=/absolute/path/to/mods runGameTestServer -x downloadAssets
```

Для локального режима ожидаются имена `kubejs-forge-2001.6.5-build.16.jar`, `rhino-forge-2001.2.3-build.10.jar`, `architectury-9.2.14-forge.jar`.
Сборка: `build/libs/bossscalingsystem-1.20.1-2.0.2.jar`. Тестовый сервер изолирован в `run-gametest`; задача кладёт туда пример скрипта KubeJS. `build` компилирует мод; серверные GameTest запускаются отдельно.

Серверные тесты покрывают формулу HP, повторную инициализацию, сферу радиуса 40, spectator, NBT сохранения моба и предмета, копии лута без общих ItemStack, видимость, подбор, воронки, слияние, исключения, отсутствие игроков и регистрацию через настоящий KubeJS.

Полный клиентский тест с двумя реальными игроками в пользовательской сборке остаётся отдельной проверкой совместимости.

## Что восстановлено и исправлено

* `recovered-2.0.1/` — необработанная декомпиляция CFR 0.152 всех классов исходного JAR. Сохраняет его фактическую логику и SRG-имена Minecraft; это справочный код, не исходный авторский проект. Исходные комментарии и Gradle из байткода восстановить нельзя.
* `src/main/` — собираемый исправленный проект с читаемыми official mappings. Это переработанная реализация, не обещание побайтового совпадения с оригиналом.
* `AUDIT.md` — найденные дефекты и принятые решения.

Сравнен `SpecialItemEntity` установленного Dungeon Now Loading 2.0 для 1.20.1: UUID владельца, фильтрация видимости и подбора. Его код и ресурсы в этот проект не копировались. Зависимости на DNL нет.
